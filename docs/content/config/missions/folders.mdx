# Task Storage

Task executors have two file-storage options: a private scratchpad for working
files and read-only [packets](/config/missions/packets) for reference material.
Neither gives the commander file access. Accepted task results and artifact
references, not a shared mutable folder, carry information between tasks.

## Attempt scratchpad

Set `scratchpad = true` on a mission to grant each task attempt a `scratchpad`
slot and the `file_list`, `file_read`, `file_view`, `file_create`, `file_delete`,
`file_search`, and `file_grep` tools:

```hcl
mission "research" {
  commander { model = models.anthropic.claude_sonnet_4 }
  models    = [models.anthropic.claude_sonnet_4]
  scratchpad = true

  task "gather" {
    objective = "Gather evidence and return a concise result"
  }

  task "summarize" {
    depends_on = [tasks.gather]
    objective  = "Summarize the accepted gather result"
  }
}
```

Each attempt gets a distinct directory under the mission run's scratchpad
root. A restarted attempt reopens its own files; a retry, sibling task, or
concurrent run cannot use that slot to read another attempt's drafts. The
run-root retention metadata lets Squadron remove scratchpads after seven days.

Tools name the slot explicitly:

```json
{ "slot": "scratchpad", "path": "notes.txt", "content": "..." }
```

If another task needs the result, submit it in the task's accepted output or
publish an artifact reference. A path in a private scratchpad is not a
cross-task handoff contract.

## Read-only packets

A mission-level packet is available to each task. A packet declared only on a
task is available only to that task. Either declaration grants the read tools
(`file_list`, `file_read`, `file_view`, `file_search`, and `file_grep`), not
`file_create` or `file_delete`. Use the `packet.<name>` slot to read it. See
[Packets](/config/missions/packets) for declarations and path rules.

## Persistent mission memory

The mission memory block defines storage shape and retention; access is granted
where each task is declared:

```hcl
memory {
  description    = "Research findings"
  retention_days = 30
  field "summary" { type = "string" }
  field "score"   { type = "number" }
}

task "research" {
  objective     = "Gather findings"
  memory_access = "read_write"
}

task "report" {
  objective     = "Summarize the findings"
  memory_access = "read"
}
```

Omitting `memory_access` grants no access. `read_write` includes read access;
`read` cannot propose updates. Fields declare allowed top-level JSON keys.
The schema supports up to 64 fields, with keys of at most 128 bytes; a task
snapshot is also capped at 64 KiB.
The worker receives a bounded snapshot of those keys when its attempt starts.
The commander cannot read mission memory or grant access to an undeclared task.
A writable worker may call `propose_mission_memory_update` with a declared key,
a JSON value matching its type, and the version from its snapshot (or `0` for
a new key). The tool records a proposal; it does not write immediately. After
the task result passes validation, the harness commits its proposals with the
task completion and audit events in one transaction. Concurrent updates to the
same key use version checks; a conflict rejects the result for retry.

`retention_days` limits how long a value remains available in future task
snapshots. An expired value is erased from the mission-memory store on its next
read while its version remains for conflict checks. It is not a promise to
erase text a worker already copied into a run transcript or artifact. Mission
memory does not grant file access. Shared-memory references via `memories` are
not part of this task-scoped capability and cannot run.

## File tools

| Tool | Purpose |
|------|---------|
| `file_list` | List files and directories |
| `file_read` | Read text with optional line or byte limits |
| `file_view` | View an image, SVG, or PDF |
| `file_create` | Create, overwrite, or append in a writable scratchpad |
| `file_delete` | Delete a file in a writable scratchpad |
| `file_search` | Search filenames by regex |
| `file_grep` | Search file contents by regex |

Paths are relative to the granted slot. Absolute paths and `..` traversal are
rejected.
