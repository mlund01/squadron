# Overview

Squadron has two closely related surfaces:

- **Configuration** describes what should exist: models, agents, tools, connections, and missions. Configuration is declarative HCL stored with the workspace.
- **The Squadron product** is where people operate that configuration: connect workspaces, manage access, run missions, inspect execution, and work with agents.

The product does not replace the Squadron runtime. A workspace has one connected Squadron worker, and that worker loads the workspace configuration and executes its missions. The product supplies the shared control plane around those workers.

## Core concepts

### Workspace

A workspace is the access and configuration boundary for one Squadron project. It owns a repository reference, a default branch, one worker connection, users and service principals, and mission permissions.

### Mission

A mission is a configured workflow with one commander and bounded task executors. Its canvas shows task dependencies, routing, and parallel execution. A run captures supplied inputs, task state, model activity, tool calls, timing, and cost telemetry.

### Agent

An agent is a configured AI capability for independent sessions, separate from mission task executors. Its model, tools, skills, and memory policy are configured for those sessions.

### Principal

A principal is an identity that can receive access. Human users receive a workspace role. Service principals are automation identities with explicit mission grants. A user may also be permitted to run a mission as a service principal.
