# Frequently Asked Questions

Common questions about Squadron — pricing, deployment, models, MCP, plugins, and how it compares to other frameworks. For an overview, start with [What is Squadron?](/).

## What is Squadron?

Squadron defines durable AI missions in HCL. Each run has one commander and
bounded task executors, with a harness that enforces the graph, capability
grants, and recovery. Managed agents are separate assistants for independent
sessions.

See [What is Squadron?](/) for the full overview.

## How much does Squadron cost?

Squadron is **free and open source** under the MIT license. You pay only for the LLM API calls you make through your own provider accounts (Anthropic, OpenAI, Google Gemini). Ollama-hosted models are free to run locally.

## Which LLM providers does Squadron support?

**Anthropic** (Claude), **OpenAI** (GPT and Responses API), **Google Gemini**, and **Ollama** for local models. A mission declares a commander model and an executor model pool; tasks can narrow that pool. Managed agents choose their own models independently.

See [Supported Models](/config/supported-models) for the current list.

## Can I self-host Squadron?

Yes. Squadron is distributed as a single Go binary that runs anywhere — your laptop, a server, a Docker container, an air-gapped environment. [Docker images](/getting-started/docker) are published to GitHub Container Registry on every release.

## Does Squadron require Python?

No. Squadron is a standalone Go binary with no runtime dependencies. Python is only required if you choose to write a Python plugin (Squadron also supports Go plugins).

## Does Squadron support the Model Context Protocol (MCP)?

**Yes — in both directions.**

- [MCP tools](/config/mcp_tools): Squadron can consume MCP servers and grant their tools to managed agents or mission task executors. Auto-install is available for `npm:` and `github.com/...` sources.
- [MCP host](/config/mcp_host): Squadron can run as an MCP server itself, exposing your missions and tools to MCP-compatible clients like Claude Desktop, Claude Code, and Cursor.

## What happens if a Squadron mission crashes mid-run?

Squadron persists the commander session, task-executor attempts, route decisions,
and results to SQLite (or Postgres) as the mission runs. Restart with:

```bash
squadron mission --resume <mission_id> -c ./config <mission_name>
```

The mission restores its durable state, including active attempts. In-flight
tool calls follow their declared replay-safety policy; uncertain calls that
cannot safely replay require intervention rather than an automatic duplicate.

## Can Squadron run scheduled or webhook-triggered missions?

Yes. Time-based schedules are created on a mission's Definition page and stored by the Squadron product. Webhook entry points remain a `trigger` block in mission configuration. The worker enforces per-mission concurrency limits for both.

See [Scheduling Missions](/product/schedules) for details.

## How does Squadron compare to LangGraph?

LangGraph is an imperative Python library built on LangChain — you write code that defines a graph and the runtime executes it. Squadron is declarative HCL configuration and a standalone Go binary — the whole workflow lives in a config file and the runtime handles state, resume, scheduling, and budgets out of the box.

See [Squadron vs LangGraph](/compare/langgraph) for the detailed comparison.

## How does Squadron compare to CrewAI?

Both are role-based multi-agent frameworks, but [CrewAI](/compare/crewai) is imperative Python with sequential or hierarchical processes, while Squadron is declarative HCL with an arbitrary DAG, conditional routing, automatic persistence and resume, scheduled missions, and budgets.

## How does Squadron compare to AutoGen?

[AutoGen](/compare/autogen) treats multi-agent collaboration as a conversation (GroupChat); Squadron treats it as a workflow (typed task DAG). AutoGen is better for emergent dialogue patterns and research; Squadron is better for deterministic production pipelines.

## How does Squadron compare to n8n?

[n8n](/compare/n8n) is a general-purpose visual SaaS-automation tool with an AI node category. Squadron is purpose-built for LLM agent workflows with a multi-agent runtime, MCP, and structured task outputs as first-class concepts. Use n8n for SaaS plumbing; use Squadron for the AI layer.

## Can non-developers edit Squadron workflows?

HCL is a simple key-value configuration language designed for human authoring (it powers Terraform). Someone comfortable with editing config files but not writing Python can read, review, and modify Squadron missions. Workflow changes show up as readable diffs in pull requests.

## How are secrets stored?

Command Center encrypts workspace variables in its database using the deployment master key. Connected workers receive the current values over their authenticated connection and keep them only in memory. Manage values from the workspace Settings page.

See [Variables](/config/variables) for the full story.

## Does Squadron support parallel execution?

Yes. Independent tasks in the DAG can run concurrently. Tasks with [iteration over a dataset](/config/missions/iteration) can also run their children in parallel. Mission-level `max_parallel` caps concurrent task work within one run.

## Can Squadron enforce a spending budget?

Yes. Missions and individual tasks can declare a `budget { tokens = ...; dollars = ... }` block. The first limit reached halts the current task and fails the mission cleanly.

See [Budgets](/config/missions/budgets) for the full mechanics.

## What language are Squadron plugins written in?

[Plugins](/config/plugins) can be written in **Go** or **Python**. They run as separate subprocesses and communicate with Squadron over gRPC via [hashicorp/go-plugin](https://github.com/hashicorp/go-plugin). Squadron auto-builds local plugins from source on every config load with content-hash caching.

## Does Squadron have a web UI?

Yes — the [Squadron product](/product/overview). Deploy it, create a workspace, then run `squadron engage` to connect the project worker with its workspace credential. The product provides mission visualization, run history, live execution, and access control.

## Can I use Squadron in production?

Yes. Squadron is designed for production from day one — persistent state, automatic resume, scheduled execution, webhook triggers, budget enforcement, structured outputs, and a single-binary deployment story. Run it under your favorite process supervisor or in Docker.
