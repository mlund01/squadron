# Squadron

**Squadron is a declarative framework for durable AI workflows.** You describe missions, task-executor model and tool policies, and the task graph in HCL. One commander coordinates each run while the harness enforces dependencies, routing, capability grants, persistence, and recovery. Managed agents are a separate way to run independent assistant sessions.

It ships as a single Go binary, runs on macOS / Linux / Windows, and is MIT-licensed.

```hcl
mission "research" {
  commander { model = models.anthropic.claude_sonnet_4 }
  models    = [models.anthropic.claude_sonnet_4]

  task "gather" {
    objective = "Find the top 5 papers on ${inputs.topic}"
  }

  task "analyze" {
    depends_on = [tasks.gather]
    objective  = "Read each paper and extract the key findings"
  }
}
```

```bash
squadron mission research -c ./config --topic "post-quantum cryptography"
```

That's the whole workflow. Diff it in a PR. Review it like infrastructure code.

## What problem does Squadron solve?

Every other agent framework asks you to write code: orchestration logic, retry loops, branching, state serialization, conversation history management. You end up with 500 lines of Python wrapping 50 lines of actual prompt — and six months later nobody can read it, nobody can resume it after a crash, and nobody can tell what changed between two runs.

Squadron flips that. The workflow is declared up front. The runtime is the engine. The only thing you write in any kind of language is the *prompts* themselves, inside `objective`/`personality` fields.

The result:

- **Code-reviewable workflows.** Workflow changes show up as a config diff, not buried in imperative orchestration logic.
- **Resilient by default.** State is persisted to SQLite (or Postgres) as missions run. Process crashes resume from the last completed step, including mid-flight LLM tool calls.
- **Policy-bound execution.** Missions grant task executors only declared models and tools. Managed-agent sessions remain independent.
- **Explicit data flow.** Tasks return accepted summaries; add typed output schemas where downstream consumers need a validated contract.

## How it works

Two tiers of LLMs, doing different jobs:

- **Commanders** coordinate one complete mission run. They dispatch eligible tasks and choose among declared routes, but cannot call task tools.
- **Task executors** do mission work with a bounded model and tool grant. Their results are validated and persisted by the harness.
- **Managed agents** are independent assistants for user or application sessions, with their own tools and configurable memory.

The commander and task executors can use different models. See [Mission Runtime](/config/missions/runtime) for the execution model.

## What's included

- **Model providers** out of the box: [Anthropic, OpenAI, Google Gemini, Ollama](/config/supported-models). Choose a commander model and an executor pool per mission.
- **[Plugins](/config/plugins)** — fast, typed, native Go *and* Python plugins for browser automation, shell access, HTTP APIs, or anything custom. Run as subprocesses over gRPC; auto-built from local source with content-hash caching.
- **[MCP tools](/config/mcp_tools)** — declare [Model Context Protocol](https://modelcontextprotocol.io) servers and grant their tools to managed agents or mission task executors.
- **[MCP host](/config/mcp_host)** — Squadron itself runs as an MCP server, so Claude Desktop / Claude Code / Cursor can see your missions and kick off runs.
- **[Schedules & webhooks](/product/schedules)** — centrally managed cron runs and configured HTTP triggers.
- **[Squadron product](/product/overview)** — workspaces, live mission visualization, run history, and access control.
- **[Budgets](/config/missions/budgets)** — declarative token + dollar caps that halt missions before runaway spend.

## When to use Squadron

Squadron is a strong fit if you want to:

- Define AI workflows the same way you define infrastructure (Terraform-style HCL).
- Have non-Python teammates author and review agent logic.
- Run scheduled or webhook-triggered agent pipelines with built-in retry, resume, and budget enforcement.
- Mix model providers across roles to control cost and latency.
- Plug Squadron into an existing MCP ecosystem without writing adapters.

Missions are not the right tool for an open-ended assistant conversation; use a managed agent for that. A deeply custom runtime loop may also be better expressed in code.

## How does it compare to other frameworks?

| Tool | Style | Language | Best for |
|---|---|---|---|
| **Squadron** | Declarative | HCL config | Production agent pipelines, reviewable workflows, scheduled jobs |
| [LangGraph](/compare/langgraph) | Imperative | Python | Custom runtime logic, deep LangChain integration |
| [CrewAI](/compare/crewai) | Imperative | Python | Quick Python prototypes, role-based crews |
| [AutoGen](/compare/autogen) | Conversational | Python | Multi-agent dialogue patterns, GroupChat |
| [n8n](/compare/n8n) | Visual | GUI / JSON | Broad SaaS integration, non-LLM-first workflows |

See the detailed comparison pages for honest tradeoffs.
