# squadron verify

Validate an HCL configuration directory.

## Usage

```bash
squadron verify <path>
```

## Arguments

| Argument | Description |
|----------|-------------|
| `path` | Path to the configuration directory |

## Example

```bash
squadron verify ./my-config
```

## Output

On success (paths and counts depend on your workspace):

```
Configuration is valid!
Storage: sqlite (/path/to/config/.squadron/store.db)
Found 1 model(s)
  - anthropic (provider: anthropic, models: [claude_haiku_4_5])
Found 0 variable(s)
Found 0 agent(s)
Found 0 custom tool(s)
Found 0 plugin(s)
Found 0 mcp server(s)
Found 0 gateway(s)
Found 1 mission(s)
  - brief (commander: claude_haiku_4_5, tasks: 2)
    Executor model pool: [claude_haiku_4_5]; optional tool pool: []
      • collect (models: mission pool; required tools: [builtins.http.get])
      • write (models: mission pool; required tools: []) [depends_on: [collect]]
```

On error, for example:

```
Error: task 'collect' timeout_seconds must be a positive whole number of seconds
```

## What Gets Validated

- HCL syntax
- Variable references (`vars.name`)
- Model references (`models.provider.model_key`)
- Tool references (`builtins.namespace.tool`, `plugins.namespace.tool`, `tools.name`)
- Mission task dependencies (no cycles)
- Dataset schemas and bindings
- Plugin install (download + checksum verify)
- Gateway install (download + checksum verify; `version = "local"` requires the binary to already exist at the cached path)

The model allow-list requires its matching connection in Squadron before
verification. To convert existing mission files, follow [Migrating Existing
Missions](/guides/migrating-missions).
